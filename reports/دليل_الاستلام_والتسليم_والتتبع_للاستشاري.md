# دليل الاستلام والتسليم وتتبع المنتجات
## نظام مصنع السلطان — وصف تشغيلي وفني دقيق للحالة الحالية

**غرض الوثيقة:** شرح دورة انتقال المنتج بين مراحل المصنع، ومسؤوليات الموظفين، وضوابط منع التكرار، وآلية الكميات المتبقية، وأثر التخزين على المستودع، والتقارير، مع تمييز واضح بين ما هو **مطبق وفعّال حالياً** وبين ما يحتاج قراراً أو معالجة قبل اعتباره سياسة تشغيلية نهائية.

> **نطاق الدليل:** هذه الوثيقة خاصة بمنتجات التصنيع التي يبدأ تاريخ سجل إنتاجها من **10/09/2026** فما بعد، وهي الفترة التي يعمل فيها النظام بمسار الانتقال الآلي المبني على سجل الإنتاج. السجلات الأقدم قد تتبع مساراً تاريخياً مختلفاً ولا ينبغي مزجها مع تقييم سلامة المسار الحالي.

---

## 1. الفكرة الحاكمة للدورة

النظام لا يعتبر كل مرحلة مخزناً مستقلاً يستطيع الموظف أن يضيف إليه منتجاً يدوياً. بل يعامل المنتج على أنه **عهدة تشغيلية موحّدة** لها مصدر واحد: سجل الإنتاج.

لكل حركة صالحة عناصر هوية أساسية تحفظ عبر المسار:

| عنصر الهوية | المصدر المعتمد | هل يمكن تغييره في المراحل؟ |
|---|---|---|
| رقم سجل الإنتاج | سجل الإنتاج | لا |
| اسم المنتج | سجل الإنتاج | لا |
| المقاس واللون | سجل الإنتاج | لا |
| الباركود | سجل الإنتاج | لا |
| رقم الماكينة والوردية | سجل الإنتاج | لا |
| تاريخ الإنتاج | سجل الإنتاج | لا |
| النخب (أول / ثانٍ / عينة) | سجل الإنتاج | لا |
| الكمية (درزن + زوج) | سجل الإنتاج والعهدة الحالية | لا في مسار التسليم الحالي |
| المسلم والمستلم وأوقات الحركة | حركة العهدة | تسجل آلياً عند تنفيذ الإجراء |

**النتيجة:** المراحل لا تنشئ منتجاً جديداً ولا تعيد تعريفه، بل تؤكد استلامه ثم تسلمه إلى المرحلة المصرح لها فقط.

## 2. خريطة سير المنتج المعتمدة

```mermaid
flowchart RL
    P[الإنتاج / مدير الإنتاج] --> R[الروسو]
    R --> Q[القلب]
    Q --> K[الكاوية]
    K --> I[الفحص]
    K --> A[مانع الانزلاق]
    A --> K
    I --> PK[التغليف]
    PK --> S[التخزين / المستودع]
    S --> WH[رصيد مستودع الإنتاج التام]
```

| المرحلة الحالية | الجهة أو المرحلة التالية المسموح بها | ملاحظة تشغيلية |
|---|---|---|
| الإنتاج | الروسو | ينشئ النظام العهدة الأولى تلقائياً بعد حفظ الإنتاج |
| الروسو | القلب | انتقال مباشر بعد تأكيد استلام الروسو |
| القلب | الكاوية | انتقال مباشر بعد تأكيد استلام القلب |
| الكاوية | الفحص **أو** مانع الانزلاق | مساران مسموحان بحسب طبيعة المنتج |
| مانع الانزلاق | الكاوية | يعود المنتج إلى الكاوية فقط |
| الفحص | التغليف | انتقال مباشر |
| التغليف | التخزين | انتقال مباشر |
| التخزين | مستودع الإنتاج التام | لا توجد مرحلة تصنيع لاحقة؛ يتم تسجيل التخزين |

> لا يستطيع المستخدم اختيار مرحلة خارج هذه الخريطة. فمثلاً لا يجوز للروسو التسليم إلى التغليف أو التخزين، ولا يجوز لمانع الانزلاق التسليم إلى الفحص مباشرة.

## 3. بداية الدورة: إدخال الإنتاج وإنشاء العهدة الأولى

### 3.1 من يملك صلاحية بدء الحركة؟

- بدء المنتج بعد تاريخ التحول محصور في **مدير الإنتاج** أو **الأدمن**.
- لا يسمح النظام لمراحل الروسو أو القلب أو الكاوية أو غيرها بإضافة منتج يدوي جديد إلى دورة العهد.
- عند محاولة ذلك يظهر رفض تشغيلي يفيد بأن المنتج يجب أن يدخل من شاشة الإنتاج ليظهر تلقائياً في قائمة الاستلام.

### 3.2 ما الذي يحدث عند حفظ دفعة الإنتاج؟

1. يدخل مدير الإنتاج بيانات المنتج: المنتج، المقاس، اللون، الباركود، الماكينة، الوردية، تاريخ الإنتاج، النخب، والكمية.
2. يختار موظفاً فعلياً ومفعلاً من **قسم الروسو** مستلماً أولياً.
3. يحفظ دفعة الإنتاج مرة واحدة، حتى لو تضمنت عدة منتجات أو ماكينات أو ورديات.
4. ينشئ النظام لكل سجل إنتاج بصمة تشغيلية تمنع تكرار الحفظ عند إعادة الضغط أو إعادة إرسال الطلب.
5. ينشئ النظام تلقائياً سجل عهدة أولي مرتبطاً برقم سجل الإنتاج ومخصصاً لموظف الروسو المحدد.
6. تظهر العهدة في قائمة استلام الروسو بحالة **بانتظار تأكيد الاستلام**.

### 3.3 ما الذي يمنع التكرار عند البداية؟

- بصمة لسجل الإنتاج تشمل عناصر التشغيل الأساسية، وليست مجرد اسم المنتج.
- مفتاح انتقال تلقائي يعتمد على: تاريخ الإنتاج + الماكينة + الوردية + هوية المنتج/المقاس/اللون/الباركود.
- إذا أعيد تنفيذ نفس الإدخال، يعيد النظام رسالة **«تم تنفيذه مسبقاً»** بدلاً من إنشاء منتج أو عهدة ثانية.

## 4. دورة الاستلام والتسليم في كل مرحلة

### 4.1 الاستلام

عند وصول المنتج إلى المرحلة التالية، يظهر في بطاقة العهدة:

- اسم المنتج.
- رقم الماكينة.
- رقم الوردية.
- تاريخ الإنتاج الأصلي.
- اللون والمقاس.
- النخب.
- الباركود.
- الكمية مفصولة إلى **درزن** و**زوج**.
- اسم المسلم والموظف المستلم المحدد.
- حالة الحركة.

يضغط الموظف المحدد زر **«استلمت»**. لا ينجح هذا الإجراء إلا إذا تحققت الضوابط التالية:

1. السجل موجود وغير محذوف.
2. الحالة الحالية هي «تم التسليم وبانتظار التأكيد».
3. المنتج مرتبط بسجل إنتاج أصلي عند دخول المسار الآلي.
4. بيانات العهدة تطابق بيانات سجل الإنتاج الأصلي: الماكينة، الوردية، التاريخ، المنتج، اللون، المقاس، الكمية، النخب والباركود.
5. الموظف الحالي هو المستلم المحدد أو — في السجلات القديمة غير المعيّنة — عضو مفعّل في القسم الصحيح فقط.
6. الموظف المستلم ليس هو الموظف الذي سلّم العهدة نفسها.
7. المرحلة الهدف مرحلة مسموح بها في خريطة التصنيع.
8. لا توجد حركة مطابقة بالكامل تمت سابقاً للبيانات نفسها.

عند نجاح الاستلام، يسجل النظام تلقائياً:

- اسم المستلم.
- وقت وتاريخ الاستلام.
- المرحلة الحالية الجديدة.
- صلة واضحة بالسجل السابق والسجل الإنتاجي الأصلي.
- سجل تتبع مستقل للاستلام.

### 4.2 التسليم

بعد تأكيد الاستلام، يصبح المنتج عهدة على الموظف المستلم في المرحلة الحالية. عند إتمام عمل المرحلة:

1. يفتح الموظف بطاقة عهده.
2. تظهر له فقط المراحل التالية التي يسمح بها المسار.
3. تظهر أسماء الحسابات **المفعلة فقط** في القسم التالي؛ لا يمكن الكتابة الحرة لاسم مستلم غير منتمٍ للقسم.
4. يختار المرحلة التالية ثم الموظف المستلم.
5. ينفذ النظام التسليم مع تسجيل اسم المسلم، المستلم، المرحلة، ووقت التسليم.
6. تصل رسالة داخلية للمستلم: «عهدة جديدة بانتظار الاستلام».
7. لا تنتقل العهدة نهائياً إلا بعد أن يضغط المستلم زر «استلمت» في حسابه.

### 4.3 حالات الحركة ومعناها

| الحالة | المعنى | من يملك الإجراء التالي؟ |
|---|---|---|
| بانتظار الاستلام / `delivered` | المسلم أنهى التسليم، والمستلم لم يثبت الاستلام بعد | المستلم المحدد فقط |
| مستلم / `received` | المستلم أكد العهدة وأصبحت تحت مسؤوليته | حامل العهدة في المرحلة الحالية |
| مكتمل مرحلة / `stageCompletedAt` | أغلقت المرحلة بالتسليم إلى مرحلة تالية أو بالتخزين | لا تعاد معالجتها من البطاقة نفسها |
| مخزّن / `STORED` | أُغلق سجل التخزين وسجلت حركته في مستودع الإنتاج التام | المستودع والتقارير فقط |
| محذوف منطقيًا | أخفاه الأدمن إلى سلة المهملات مع بقاء سجل التدقيق | الأدمن يستطيع الاسترجاع خلال 30 يوماً |

## 5. الضوابط الرقابية الأساسية

### 5.1 منع أن يسلم الموظف لنفسه

النظام يفحص الهوية بالاسم واسم المستخدم ومعرّف الحساب عند الإمكان. إذا كان المسلم والمستلم الشخص نفسه يرفض الإجراء برسالة:

> «لا يجوز للموظف نفسه تسليم واستلام نفس العهدة».

ويشمل ذلك الأسماء التشغيلية التي قد تحتوي لقباً أو فاصلة أو شرطة.

### 5.2 منع التسليم إلى موظف غير مؤهل

المستلم يجب أن يكون:

- حسابه مفعّلاً.
- منتمياً إلى القسم/المرحلة المستهدفة وفق قائمة الأقسام الرسمية.
- مختلفاً عن المسلم.

لا يكفي أن يكتب المستخدم اسماً متشابهاً؛ الخادم يتحقق من الحساب الفعلي وقسمه.

### 5.3 منع تكرار الضغط أو إرسال الجوال المتزامن

يوجد قفل ذري على الحالة:

- الاستلام لا ينفذ إلا عندما تكون الحالة `delivered`.
- التسليم لا ينفذ إلا عندما تكون الحالة `received`.
- أول طلب ناجح يغير الحالة؛ أي طلب متزامن أو ضغط لاحق يفشل برسالة **«تم تنفيذه مسبقاً»**.
- إذا كانت الحركة أنشئت بالفعل في طلب سابق وتأكد النظام من السجل الناتج، يعيد نتيجة ناجحة غير مكررة بدلاً من إنشاء صف ثانٍ.

### 5.4 منع تعديل هوية المنتج داخل المراحل

بعد بداية المسار الآلي، لا يمكن لموظفي المراحل تعديل المنتج أو كميته أو الباركود أو رقم الماكينة أو الوردية. تصحيح الهوية الأساسية محصور بمدير الإنتاج أو الأدمن، وبحقول محددة فقط، مع سجل تدقيق.

### 5.5 منع التكرار المطابق لا المنتجات المتشابهة

لا يمنع النظام منتجين لمجرد تشابه الاسم والكمية. يعتبر الحركة مكررة فقط إذا تطابقت كل عناصر الهوية الأساسية. لذلك اختلاف الماكينة أو الوردية أو تاريخ الإنتاج أو الباركود أو المقاس أو اللون يسمح بحركة مستقلة صحيحة.

## 6. الحالة الخاصة: مانع الانزلاق

مانع الانزلاق هو المرحلة الوحيدة التي لها قيد تسلسلي خاص مطبق من الخادم نفسه:

1. تستلم مانع الانزلاق من **الكاوية فقط**.
2. لا يسمح لمانع الانزلاق باستلام دفعة جديدة من الكاوية ما دامت توجد دفعة سابقة مستلمة ولم تعد إلى الكاوية.
3. عند محاولة ذلك، تظهر رسالة توضح أن المنتج السابق يجب أن يعاد إلى الكاوية أولاً، مع إظهار اسم المنتج السابق عند توفره.
4. تعيد مانع الانزلاق المنتج إلى **الكاوية فقط**؛ لا يملك اختيار الفحص أو التغليف أو التخزين.

هذا القيد يمنع اختلاط دفعات مانع الانزلاق ويضمن أن الكاوية تستعيد المنتج قبل دفعه إلى الفحص.

## 7. الكميات: الدرزن والزوج والتسليم الجزئي

### 7.1 قاعدة التحويل

النظام يحول أي كمية إلى أزواج عند الحساب الداخلي:

> إجمالي الأزواج = (عدد الدرزن × 12) + عدد الأزواج

ثم يعيد عرض الناتج بصيغة «درزن + زوج». مثال: 38 زوجاً = 3 درزن + 2 زوج.

### 7.2 ما هو مطبق فعلياً في واجهة ومسار التسليم الآن؟

**التسليم الحالي ينقل كامل كمية العهدة فقط.**

- زر التسليم يرسل كمية البطاقة كما استلمت.
- الخادم يقارن الكمية المرسلة بكمية العهدة ويرفض أي كمية مختلفة.
- لذلك لا يستطيع الموظف في الشاشة الحالية أن يختار مثلاً تسليم 40 درزن من عهدة 50 درزن وترك 10 درزن.

### 7.3 منطق الكميات المتبقية الموجود في النظام

قاعدة البيانات والتقارير تحتوي منطقاً لاستيعاب التسليم الجزئي عند توفره:

- يحسب المتبقي بالأزواج.
- ينشئ عهدة متبقية باسم الموظف نفسه وفي المرحلة نفسها.
- يسجل المتبقي في تقرير **الكمية المتبقية** مع اسم المنتج، اللون، المقاس، المرحلة، والكمية.
- ينشئ تنبيهاً للأدمن عند وجود كمية متبقية.
- عند تسليم المتبقي لاحقاً، يغلق سجلات المتبقي المطابقة ويضيف ملاحظة «تم تسليم الكمية المتبقية لاحقاً».

> **ملاحظة استشارية جوهرية:** منطق الخلفية والتقرير موجود، لكن واجهة التسليم الحالية والخادم يمنعان إدخال كمية أقل من كمية العهدة. لذلك ميزة التسليم الجزئي ليست متاحة عملياً للمستخدم النهائي الآن، رغم وجود البنية البرمجية الداعمة لها. يلزم تنفيذ شاشة كمية تسليم فعلية مع تحقق يضمن أن الكمية لا تتجاوز العهدة وأن سجل المتبقي ينشأ تلقائياً.

### 7.4 الفرق بين المستلم والمسلّم والمتبقي في التقرير

| المؤشر | تعريفه |
|---|---|
| المستلم | ما أكد الموظف استلامه فعلياً في الفترة |
| الرصيد السابق | كمية متبقية من قبل بداية نطاق التقرير |
| المتاح للتسليم | الرصيد السابق + ما استلم في الفترة |
| المسلّم | ما سلّمه الموظف فعلياً، وبحد أقصى لا يتجاوز المتاح |
| المتبقي | المتاح للتسليم − المسلّم |
| فرق الاستلام والتسليم | المستلم/المتاح ناقص المسلّم وفق مستوى التقرير |

يفصل التقرير الفرق بصرياً:

- **موجب بالأزرق:** يحتاج مراجعة؛ يشير إلى كمية متاحة لم تسلم أو إلى اختلاف يتطلب جرداً.
- **سالب بالأحمر:** نقص يحتاج تحققاً.
- كما ينشئ النظام تنبيهاً للأدمن عند وجود فرق موجب في ملخص مسؤولية الموظفين.

## 8. التخزين وربط المنتج بمستودع الإنتاج التام

### 8.1 ما الذي يحدث عند وصول المنتج إلى التخزين؟

1. يقوم موظف التغليف بتسليم المنتج لموظف التخزين المحدد.
2. يؤكد موظف التخزين الاستلام من بطاقة العهدة.
3. يتأكد النظام من وجود الباركود ومن مطابقته لباركود الإنتاج الأصلي.
4. ينشئ النظام سجل تخزين بنفس هوية المنتج الأصلية.
5. عند تأكيد استلام التخزين، يضيف النظام تلقائياً حركة **وارد** إلى مستودع الإنتاج التام ويزيد رصيد الصنف.
6. عند ضغط «حفظ التخزين بالبيانات الأصلية»، يغلق النظام بطاقة مرحلة التخزين كعملية مكتملة ولا يعيد زيادة الرصيد إذا كانت حركة الوارد سُجلت سابقاً.

### 8.2 ضمان عدم تكرار حركة المستودع

حركة المستودع مرتبطة بمصدر العهدة التخزينية. قبل إضافة حركة وارد جديدة، يفحص النظام ما إذا كانت حركة صادرة من المصدر نفسه موجودة بالفعل. إذا كانت موجودة، لا يضيف كمية مرة أخرى.

### 8.3 تنبيه الحد الأدنى

لكل صنف حد أدنى افتراضي مقداره 50 درزن. عند انخفاض الرصيد المسجل عن الحد الأدنى بعد حركة تخزين/مخزون، ينشئ النظام رسالة داخلية موجهة إلى قسم المستودع.

### 8.4 قيد وحدات مستودع الإنتاج التام

> مخزون الإنتاج التام وحركاته يخزنان ويحسبان **بالدرزن فقط** في البنية الحالية. كمية الأزواج موجودة في العهدة والتتبع، لكنها لا تُضاف كوحدة مستقلة إلى رصيد المستودع النهائي.

هذا يمثل قيداً محاسبياً وتشغيلياً إذا كان المصنع يعتمد على أرصدة غير مكتملة الدرزن. التوصية هي توحيد نموذج المخزون مع التتبع بإضافة `quantityPairs` أو التخزين الداخلي بالأزواج وإظهار الدرزن/الزوج في الواجهة.

## 9. الأوقات والتأخير

### 9.1 الأوقات المسجلة

تسجل كل حركة رئيسية وقتاً مستقلاً:

| الحقل | معنى الوقت |
|---|---|
| وقت التسليم | وقت اعتماد المسلم لخروج العهدة من مرحلته |
| وقت الاستلام | وقت ضغط المستلم زر «استلمت» |
| بداية المرحلة | بداية احتساب العمل في المرحلة إن وجدت في سجل التتبع |
| اكتمال المرحلة | وقت تسليمها للمرحلة التالية أو إغلاق التخزين |

لا يعتمد التقرير على تاريخ الإنتاج وحده لقياس زمن المرحلة؛ يستخدم أوقات الاستلام والتسليم/الإكمال المتاحة.

### 9.2 تنبيه العهد المتأخرة

- إذا بقيت العهدة بحالة «مستلم» أكثر من **24 ساعة زمنية**، يظهر تنبيه لصاحب العهدة ويظهر في تقرير العهد المتأخرة للأدمن/المدير/المشرف.
- التنبيه اليومي يحث الموظف على تسليم العهدة قبل استلام منتج جديد.

> **تنبيه استشاري:** 24 ساعة زمنية ليست هي نفسها «يوم عمل من 8 ساعات». إذا كانت سياسة المصنع تقيس التأخير بساعات الدوام والورديات، يلزم وجود تقويم ورديات وساعات عمل وإجازات، ثم حساب SLA بناء عليها. النظام الحالي لا ينفذ هذا الحساب المتقدم.

## 10. الشاشات والتقارير المتاحة

### 10.1 شاشة المرحلة التشغيلية

لكل مرحلة شاشة تعرض بطاقات العهدة. البطاقة تظهر هوية المنتج، الكميات، الحالة، أوقات الاستلام والتسليم، وأزرار الإجراء المسموح به فقط:

- **استلمت** عند وصول عهدة مخصصة للموظف.
- اختيار المرحلة والموظف التالي عند وجود عهدة مستلمة قابلة للتسليم.
- **حفظ التخزين بالبيانات الأصلية** داخل التخزين.
- زر تحديث لمزامنة إجراءات الجوال.
- تقرير مرحلة يومي/أسبوعي/شهري مع موظف محدد أو كل الموظفين للأدمن.

### 10.2 شاشة الكمية المتبقية

تعرض السجلات التي تحتوي كمية غير مسلمة، مع تفاصيل المنتج والمرحلة والمقاس واللون والكمية، وتدعم تصدير Word وExcel.

### 10.3 التقرير الشامل

يقدم التقرير الشامل:

- مؤشرات الإنتاج والخيوط والهدر.
- أعداد وحالات الاستلام والتسليم والتعليق.
- المتبقي في مراحل التصنيع.
- ملخصاً مستقلاً لكل مرحلة: الرصيد السابق، المستلم، المتاح، المسلّم، المتبقي، الفرق، ومدة المرحلة.
- ملخص مسؤولية الموظفين.
- تفاصيل حركة الاستلام والتسليم: المنتج، المسلم، المستلم، وقت التسليم ووقت الاستلام.
- تفاصيل حركة المستودع، المبيعات والطلبات، التحصيل، المصروفات، الصيانة، المهام، الإجراءات الإدارية والمنتجات بحسب النطاق المختار.

### 10.4 تقرير تتبع المنتج

تقرير تفصيلي للسجل التشغيلي يمكن من خلاله مراجعة مسار المنتج من الإنتاج حتى التخزين، ومقارنة الكميات والجهات والتوقيتات.

## 12. أمثلة تشغيلية مختصرة

### مثال 1: مسار عادي كامل

1. مدير الإنتاج يسجل: منتج SP1، مقاس M، أبيض، ماكينة 2، وردية 1، باركود SP1-M-W-001، كمية 4 درزن + 6 زوج، ويختار موظف روسو.
2. تصل بطاقة إلى موظف الروسو بحالة بانتظار الاستلام.
3. موظف الروسو يؤكد الاستلام؛ يسجل اسمه ووقته.
4. الروسو يختار موظفاً مفعلاً من القلب ويسلمه نفس هوية المنتج ونفس الكمية.
5. القلب يؤكد الاستلام ثم يسلم للكاوية.
6. الكاوية تسلم للفحص أو لمانع الانزلاق حسب المنتج. إذا ذهب لمانع الانزلاق، يعود بعده للكاوية.
7. الفحص يسلم للتغليف، والتغليف للتخزين.
8. التخزين يؤكد الاستلام؛ يسجل النظام حركة وارد في مستودع الإنتاج التام بالباركود نفسه.

### مثال 2: محاولة استلام الموظف لعهدته التي سلمها بنفسه

- يرفض النظام الإجراء لأن فصل المهام يمنع أن يكون الشخص نفسه مسلماً ومستِلماً للحركة ذاتها.

### مثال 3: ضغط زر الاستلام مرتين أو من الهاتف والكمبيوتر معاً

- أول طلب فقط ينجح ويغير الحالة.
- الطلب الآخر لا ينشئ حركة إضافية ويظهر «تم تنفيذه مسبقاً» أو يعيد الحركة المؤكدة نفسها دون تكرار.

### مثال 4: محاولة تسليم الروسو إلى التخزين

- يرفض النظام لأن المرحلة التالية الوحيدة للروسو هي القلب.

### مثال 5: إدخال منتج جديد من شاشة القلب

- يرفض النظام للحركات الحديثة، لأن المنتج يجب أن يأتي من سجل الإنتاج الأصلي.

## 13. تقييم الحالة الحالية: ما هو مكتمل وما يحتاج معالجة

### 13.1 ضوابط مطبقة وفعالة

- مصدر واحد للمنتج من سجل الإنتاج.
- سلسلة مراحل مقيدة ومسارات انتقال محددة.
- اختيار موظف مفعّل من القسم المستهدف.
- منع التسليم والاستلام للنفس.
- منع الحفظ المكرر والضغط المتزامن.
- الحفاظ على هوية المنتج والباركود والماكينة والوردية والتاريخ والنخب.
- منع التعديل اليدوي من مراحل التصنيع الحديثة.
- سجل تتبع للاستلام والتسليم والأوقات.
- ربط التخزين بحركة وارد ورصيد مستودع الإنتاج التام.
- تنبيهات العهد المتأخرة بعد 24 ساعة.
- سلة مهملات إدارية قابلة للاسترجاع خلال 30 يوماً.

### 13.2 فجوات يجب عدم تجاهلها

| الأولوية | الفجوة الفعلية | الأثر | التوصية |
|---|---|---|---|
| عالية جداً | لا توجد واجهة/مسار فعلي لتسليم جزء من العهدة؛ الخادم يفرض كامل الكمية | الكميات المتبقية لا تنشأ من العمل اليومي رغم وجود منطقها | إضافة شاشة تسليم جزئي مع إدخال درزن/زوج، تحقق من الرصيد، وإنشاء عهدة متبقية تلقائياً |
| عالية جداً | رصيد مستودع الإنتاج التام يحفظ الدرزن فقط دون الأزواج | فقدان دقة الرصيد عند وجود كميات غير مكتملة الدرزن | إضافة الأزواج في مخزون وحركة المستودع أو جعل وحدة التخزين الأساسية زوجاً |
| عالية | منع استلام منتج جديد قبل تسليم السابق مطبق إلزامياً في مانع الانزلاق فقط | بقية المراحل قد تحمل عدة عهد في الوقت نفسه خلاف السياسة المطلوبة إن كانت عامة | توحيد القاعدة على كل المراحل أو تعريف الاستثناءات بقرار إداري |
| عالية | تنبيه تأخر العهدة يعتمد 24 ساعة زمنية | لا يطابق ساعات/ورديات العمل الفعلية | بناء محرك SLA يعتمد ورديات المصنع، أيام العمل والإجازات |
| متوسطة | التخزين يزيد الرصيد عند تأكيد استلام التخزين، ثم يغلق الموظف بطاقة التخزين بزر مستقل | يلزم اتفاق تشغيلي: هل يعتبر الرصيد متاحاً عند الاستلام أم بعد الفحص/الحفظ النهائي؟ | اعتماد نقطة ملكية رسمية للمخزون وتسمية الحالات بوضوح |
| متوسطة | بعض السجلات التاريخية قبل التحول قد لا تطابق قواعد المصدر الواحد | قد تشوش التقارير والجرد إذا خلطت بالفترة الحديثة | فصل التقارير قبل/بعد تاريخ التحول وتنظيف/أرشفة السجلات التاريخية بعد مراجعة |
| متوسطة | التنبيه عن العهدة المتأخرة ينشأ عند قراءة قائمة العهدة | قد لا يصل التنبيه إذا لم يفتح الموظف/الخدمة الشاشة | تشغيل مهمة خادمية مجدولة أو Trigger يفحص العهد المتأخرة مستقلاً عن فتح الشاشة |

## 14. قرارات مطلوبة من الاستشاري والإدارة قبل اعتماد السياسة النهائية

1. **هل يسمح بالتسليم الجزئي؟**
   - إن كانت الإجابة نعم: اعتماد نموذج درزن/زوج، سبب النقص، حالة المنتج المتبقي، وهل المتبقي يعاد تسليمه للمرحلة نفسها أو يبقى مع الموظف تلقائياً.

2. **هل قاعدة «لا تستلم الجديد قبل تسليم السابق» تطبق على كل مرحلة أم على مانع الانزلاق فقط؟**
   - تطبيقها على الجميع يبسط الجرد لكنه قد يعرقل التدفق إذا كان الموظف يعالج عدة موديلات بالتوازي.

3. **متى يصبح المنتج مخزوناً متاحاً للبيع؟**
   - عند تأكيد الاستلام في التخزين، أو بعد «حفظ التخزين»/فحص باركود/جرد مستقل؟

4. **ما وحدة المخزون الرسمية؟**
   - زوج كأساس حسابي، مع عرض درزن + زوج، هو الخيار الأدق لتفادي كسر الدرزن.

5. **ما مهلة كل مرحلة وفق الورديات؟**
   - يلزم اعتماد SLA لكل مرحلة، ووضع جدول ورديات وإجازات، ثم ربط التنبيه والتصعيد بهذه البيانات.

6. **كيف تتعامل الإدارة مع بيانات ما قبل 10/09/2026؟**
   - تقرير تاريخي مستقل، أو مراجعة وتسوية أولية، أو استبعادها من مؤشرات التشغيل الجديدة.

## 15. ملخص تنفيذي للاستشاري

> النظام مبني على مبدأ صحيح: **إنتاج واحد → عهدة واحدة قابلة للتتبع → تأكيد استلام مستقل → تسليم مقيد لمسار وموظف محددين → تخزين مرتبط بالباركود → سجل وتقارير قابلة للمراجعة**.

أقوى عناصره الحالية هي حفظ هوية المنتج من المصدر، منع التكرار، فصل المسلم عن المستلم، تقييد انتقال المراحل، وتسجيل أوقات وأسماء الحركات.

أما الإغلاق التشغيلي المطلوب قبل اعتماد النظام كضبط جرد كامل فهو:

1. تفعيل التسليم الجزئي فعلياً لا نظرياً.
2. توحيد المستودع على الدرزن والزوج أو الزوج كأساس.
3. حسم وتطبيق قاعدة العهدة الواحدة لكل موظف/مرحلة إن كانت سياسة المصنع.
4. استبدال تنبيه الـ24 ساعة بساعات عمل وورديات معتمدة.
5. عزل أو تسوية البيانات التاريخية قبل تاريخ التحول حتى لا تؤثر على دقة التقارير.
